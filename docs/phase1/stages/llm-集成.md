# LLM 集成（追加发布）

## 目标

给系统加"AI 解读"能力，但严格守住一条硬约束：**大模型绝不直连数据库**。落地三个能力——早盘简报解读、术语解释、项目问答（基于静态知识库），并接入每日 09:20 定时飞书卡片。

> 本迭代不属于路线图的编号 Iteration，是第一条主线（可观测通知）的自然延伸——简报推送有了，简报"读得懂"就是 LLM 的价值。

## 设计

1. **三大能力**：
   - 简报解读：解读当日早盘简报 → 09:20 定时推送飞书卡片；
   - 术语解释：单术语 ≤200 字；
   - 项目问答：基于静态知识库（`docs/llm/术语表.md` + `docs/llm/项目知识.md`）检索回答。
2. **静态知识库 + 只读挂载**：知识库是 markdown 文件，发布时随发布包打包、以**只读**方式挂载进 backend 容器（`6cdc372` 修复前生产容器没有知识库 → LLM 功能不可用）。
3. **LLM 绝不直连 DB（硬约束）**：大模型唯一的项目数据入口是**白名单只读接口 `BriefReader`**——防止大模型被注入或读取敏感数据。这是与"知识库问答"并列的第二类数据来源（白名单只读），其余一律不接触数据库。
4. **云端 API**：支持 openai / deepseek / qwen / glm 四种 provider，配置在页面「设置」（`app_config.llm.*`，沿用"业务配置全走页面"原则）。
5. **围栏与健壮性**：模型输出限长、失败重试、服务级围栏——对应测试 `28ee7dc`（围栏/重试/限长/集成）。
