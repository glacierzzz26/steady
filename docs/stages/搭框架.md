# 第一阶段 · 搭框架（Sprint 0-6）

## 目标

从零搭起个人 A 股量化研究与模拟交易平台的骨架：五个服务（collector / quant-engine / backend / frontend / postgres）能本地跑通，形成"拉数据 → 算因子 → 出信号 → 模拟交易 → 看净值"的完整闭环。**先让功能存在**，可靠性和可观测性留给后续 Iteration。

## 设计

定稿设计原文见 [`../design/设计思路.md`](../design/设计思路.md)（08-19）与 [`../design/技术准备文档.md`](../design/技术准备文档.md)（08-20）。核心决策浓缩：

1. **数据驱动 + 单机部署**：服务间不互调 HTTP，PostgreSQL 是唯一通信中枢；不上 k8s，单机 docker-compose。
2. **四原则**：数据可靠 > 策略复杂；可解释策略 > 黑盒模型；模拟验证 > 实盘尝试；长期复利 > 短期暴利。
3. **五服务**：collector（Python 采集）、quant-engine（Python 因子/信号/回测/通知）、backend（Go REST + 模拟交易）、frontend（React+TS）、postgres/nginx。
4. **模拟盘定位**：不接券商，模拟撮合全在 DB；真实现单是 Phase 3 预留方向（`backend/internal/service/broker.go:55` 注释"模拟券商成交（纯函数，不持有状态）"）。
5. **多因子轮动唯一策略**：6 因子（趋势 ma_trend/macd_signal 各 0.20、价值 pe/pb 各 0.15、质量 roe 0.20、风险 debt 0.10）+ 横截面归一 + 综合分排名 + 轮动缓冲带（排名 ≤15 买 / >30 卖），`strategy.params` 配置 `top_n=20 / buy_buffer=15 / sell_buffer=30 / max_position_pct=0.20`。

> 规划了 `momentum.py` 动量策略，但未实现（仅占位），系统只有 `multi_factor` 一个策略。

## 验收

- ✅ 本地五服务 docker-compose 起得来，数据链路"采集 → 因子 → 信号 → 模拟交易 → 净值"能跑通
- ✅ 前端六个页面能看真实数据（股票列表 / 个股 K 线 / 策略信号 / 模拟交易 / 回测 / Dashboard）
- ✅ 模拟撮合还原 A 股规则：收盘价 ±0.1% 滑点、100 股整手、T+1 冻结、涨停拒买/跌停拒卖、佣金万 2.5 最低 5 元、印花税万 5 仅卖出
- ✅ 因子计算做 as-of 防未来函数（财务只取 `announce_date <= trade_date`、估值 as-of 30 日回看、行情用前复权价）
- ⚠️ 已知 look-ahead 风险点（阶段内已知并接受）：行情类因子"当日收盘算信号、当日收盘价成交"，真实盘中不成立——列入 Iteration 3 最高优先校准项

## 遗留

1. 数据源只有 AkShare 兜底链路，无 Tushare 主源（→ Iteration 0）
2. 无任何通知能力，跑没跑、成没成不可见（→ Iteration 1）
3. 回测存在 look-ahead 风险（T 日收盘信号 + T 日收盘成交），需做 T vs T+1 成交对比验证（→ Iteration 3）
4. `momentum.py` 策略占位未实现
