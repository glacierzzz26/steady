## 3. 数据可行性（零新增费用，纯代码）

IC 计算要素**全部在库**：

- 因子值：`factor_value.rank/normalized`（横截面，方向统一）✅
- 前向收益：`daily_price.close × adj_factor / 窗口最新 adj_factor`（前复权，与因子计算同口径）✅
- 股票池：`stock_basic.universe in (hs300, zz500)` ✅
- 交易日序列：`trade_calendar` ✅

**防未来函数（研究地基）**：IC 口径 = 因子值在 T 日（`factor_value` 由 as-of 窗口计算，不含 T 日之后信息）对 **T→T+H 前向收益**（严格在 T 之后）求秩相关。天然无 look-ahead，与 Iteration 3 的 T+1 校准同源。**这是本阶段要明确写死的研究纪律。**

## 4. 关键设计决策

### 4.1 IC 计算口径（固定约定）

- **Rank IC**：横截面 Spearman 秩相关，`corr(rank(因子值@T), rank(前向收益@T→T+H))`。用 `factor_value.rank`（已方向统一），方向天然处理——正 IC = 因子方向正确。
- **前向收益**：`qfq_close[T+H] / qfq_close[T] - 1`；停牌/缺失该股票该点不参与当日横截面。
- **IC 序列**：对区间内每个交易日 T 算一个 IC → 时序。
- **ICIR**：`mean(IC) / std(IC)`（年化 `×sqrt(252/H)`，前端展示口径注明）。
- **IC 衰减**：同一区间分别按 H∈{1,5,10,20,60} 算 IC → 衰减曲线。
- **分层收益**：每交易日按因子分为 Q=5 组，组均前向收益（H=5），跨日平均 → Q 条收益线；单调性 = Q1(最优) 收益显著高于 Q5。
- **相关性矩阵**：6 因子两两 Spearman 秩相关（对横截面归一值），跨日平均。

### 4.2 计算归属与服务模型（核心决策，2026-08-25 定稿修正）

**修正结论**：IC 等统计数学**全部收在 quant-engine（Python/pandas）单实现**，G9/G10 共用同一份代码；backend Go 只做「读表 + 轻聚合」（mean/std/比值/矩阵平均）。避免两套 IC 实现漂移导致 FactorLab 与试算数字不一致——这是研究平台最不可接受的失败模式。

| 能力 | 计算归属 | 服务模型 | 理由 |
|---|---|---|---|
| **G9 检验统计**（IC/ICIR/分层/衰减/相关性） | **quant-engine Python 预计算** `factor_stat`/`factor_corr` 表 | `GET /factors/:name/stats` 从表读行 + Go 轻聚合 | 单一 IC 实现、pandas 正确性、数字与试算必然一致；per-date 追加表使任意区间查询精确 |
| **G10 试算/寻优**（参数化重算因子） | **quant-engine Python 异步** | `factor_trial` DB 队列 + 每 5 分钟消费，复用 backtest_job 模式 | 复用同一份 IC 函数，试算结果与 FactorLab 同口径；参数化重算走已验证的因子代码路径 |

**为什么 Go 现算被否掉（记录否决理由）**：交互页要"实时"是伪需求——**H=60 的 IC 无论谁算都注定滞后 60 个交易日**（要等前向收益走完），短 horizon 每日刷新已足够。为此牺牲"两套实现必然一致"和 pandas 的成熟正确性，不划算。Go 侧只留轻聚合，避免手写秩相关/分层的隐性出错。

**新鲜度模型**：`factor_stat` 按 (因子, 交易日) **追加**，任意子区间 = 读对应行，无缓存失效。horizon 固定 {1,5,10,20,60}（对齐 mock 的 1~60 日衰减曲线）；临时要其他 horizon 走 G10 试算（异步）。

### 4.3 G10 试算的现实边界（如实说明）

现有 6 因子公式硬编码在 `factor_service.factor_raw_value`，**任意新公式无法仅靠 formula 字符串自动计算**。故 G10 试算定位为：**对已有因子做参数化重算 + 检验**（如 MA 窗口、MACD 快慢线、持有期），而非任意新公式。寻优热力图 = 参数网格 × 持有期的 IC。前端「新公式模板」保留为产品愿景标注（需要公式 DSL 时另起阶段）。

## 5. Schema 变更（迁移 `deploy/migrations/002_*`）

`factor_definition` 增加版本与状态（幂等，对齐 migrate.sh 惯例）：

```sql
ALTER TABLE factor_definition ADD COLUMN IF NOT EXISTS version VARCHAR(20) NOT NULL DEFAULT 'v1.0';
ALTER TABLE factor_definition ADD COLUMN IF NOT EXISTS status  VARCHAR(10) NOT NULL DEFAULT 'active';
```

新增 `factor_stat`（G9 检验统计，per-date 追加，quant-engine 预计算 / Go 读取聚合）：

```sql
CREATE TABLE IF NOT EXISTS factor_stat (
    id           BIGSERIAL PRIMARY KEY,
    factor_name  VARCHAR(50) NOT NULL REFERENCES factor_definition(name),
    trade_date   DATE NOT NULL,
    ic_1d   NUMERIC(12,6),  -- T→T+1 横截面 Rank IC
    ic_5d   NUMERIC(12,6),  -- T→T+5
    ic_10d  NUMERIC(12,6),
    ic_20d  NUMERIC(12,6),
    ic_60d  NUMERIC(12,6),
    q1 NUMERIC(12,6), q2 NUMERIC(12,6), q3 NUMERIC(12,6), q4 NUMERIC(12,6), q5 NUMERIC(12,6),
    -- 当日 5 分层组均前向收益（H=5，Q1=因子最优组）
    UNIQUE (factor_name, trade_date)
);

-- 因子两两相关性（6×6，per-date，Go 读区间做矩阵平均）
CREATE TABLE IF NOT EXISTS factor_corr (
    id          BIGSERIAL PRIMARY KEY,
    trade_date  DATE NOT NULL UNIQUE,
    matrix      JSONB NOT NULL   -- [[...6x6...]]
);
```

新增 `factor_trial`（G10 试算任务，对齐 backtest_job 模式）：

```sql
CREATE TABLE IF NOT EXISTS factor_trial (
    id          BIGSERIAL PRIMARY KEY,
    factor_name VARCHAR(50)  NOT NULL REFERENCES factor_definition(name),
    params      JSONB,                          -- 试算参数（如窗口/持有期网格）
    status      VARCHAR(16) NOT NULL DEFAULT 'pending',  -- pending/running/done/failed
    result      JSONB,                          -- IC/ICIR/分层单调性/热力图数据
    error       TEXT,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    finished_at TIMESTAMPTZ
);
```

Go 侧 `FactorDefinition` 模型补 Version/Status 字段，新增 `FactorStat`/`FactorTrial` 模型。

## 6. 接口契约

### 6.1 G9 FactorLab

**`GET /factors`**（已有，微调）——返回含 version/status/weight 的因子定义列表。

**`GET /factors/:name/stats?start=YYYY-MM-DD&end=YYYY-MM-DD&horizon=5`**（新增）

- **数据来源：`factor_stat` 表**（quant-engine 预计算），Go 读行 + 轻聚合（mean/std/衰减）。
- 区间上限：默认最近 2 年，`end-start` 超过 5 年拒绝（与 backtest 同纪律）。
- horizon 取 {1,5,10,20,60} 预计算列；`horizon` 参数只影响主 IC 序列/ICIR 用哪列（默认 5）。
- 响应（一次性给齐 FactorLab 页数据）：

```json
{
  "factor": "ma_trend", "category": "trend",
  "range": {"start": "2024-08-25", "end": "2026-08-25", "days": 486},
  "horizon": 5,
  "ic_series": [{"date": "2024-08-26", "ic": 0.031, "ic_5d": null}, "..."],
  "icir": 0.31, "ic_mean": 0.021, "ic_std": 0.068,
  "ic_decay": [{"horizon": 1, "ic": 0.012}, {"horizon": 5, "ic": 0.021}, {"horizon": 10, "ic": 0.019}, {"horizon": 20, "ic": 0.014}, {"horizon": 60, "ic": 0.008}],
  "quantiles": [{"group": 1, "ret": 0.0041}, {"group": 2, "ret": 0.0022}, {"group": 3, "ret": 0.0008}, {"group": 4, "ret": -0.0009}, {"group": 5, "ret": -0.0027}],
  "monotonic": 0.82
}
```

**`GET /factors/stats/correlation`**（新增，一次性给 6×6 矩阵）：

- **数据来源：`factor_corr` 表**（quant-engine 预计算 per-date 6×6），Go 读区间做矩阵平均。
- 默认最近 1 年。

```json
{ "factors": ["ma_trend", "macd_signal", "pe_ratio", "pb_ratio", "roe_quality", "debt_risk"],
  "matrix": [[1, 0.12, -0.05, ...], ...] }
```

### 6.2 G10 FactorFactory

**`POST /factors`** 新建因子（草稿）；**`PUT /factors/:name`** 编辑（仅草稿/停用可改）；**`DELETE /factors/:name`** 删除（仅草稿，有试算/引用则拒）。

**`POST /factors/:name/versions`** fork 新版本（`v1.0 → v2.0`，含 params 快照）。

**`POST /factors/:name/trial`**（新增，异步）——body `{ "params": {...}, "start": "...", "end": "..." }`，创建 `factor_trial`(pending)，返回 trial id。

**`GET /factor-trials/:id`**（新增）——pending/running 返回状态；done 返回 `{ "ic_series", "icir", "quantiles", "monotonic", "heatmap"? }`。

**`POST /factors/:name/optimize`**（新增，异步）——body `{ "param_grid": {"window": [5,10,20,30], "horizon": [5,10,20]}, "start": "...", "end": "..." }`，创建寻优 trial，done 返回热力图数据 `{ "windows": [...], "horizons": [...], "grid": [[...]] }`。

> 状态流转沿用 strategy 状态机模式（草稿→试算→检验→上线→停用），约束：仅 active 因子进入评分池（`factor_service` 只算 active 因子）。
