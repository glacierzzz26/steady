# Iteration 4：策略与风控（G11 策略生命周期 + 风控落执行层）

> 归档模板：每个阶段一页，按五节填写。定稿设计见 [`../design/策略与风控.md`](../design/策略与风控.md)。
> 关联：接口契约 [`frontend-v2-api-contract.md`](../design/frontend-v2-api-contract.md) G11 · 进度总表 `../../进度总表.md`。

## 目标

把「策略」从硬编码单例提升为**一等的生命周期对象**，并让权重、参数、风控都在**策略行**上可配置：

1. **多策略生命周期**：状态机（草稿→回测验证→样本外验证→运行中→暂停/归档）、单 active 不变量、fork 版本化——信号生成与实盘执行从「写死 multi_factor」改为**读 active 策略**。
2. **权重/参数前端配置**：策略自带**因子级权重**（覆盖 factor_definition），StrategyFactory 构建器接通真实 API。
3. **回测多策略 + A/B**：`POST /backtests` 指定策略、`GET /strategies/compare` 同区间同假设对比。
4. **风控落执行层**：止损 / 回撤熔断 / 行业集中 在 **Go 实盘 + Python 回测同口径**生效。
5. **风险指标**：turnover（年化单边换手）/ cost（年化交易成本占比）进回测结果 + 前端点亮。

## 设计

核心决策（详见[定稿设计](../design/策略与风控.md)）：

1. **状态机**：`draft → backtest → sample → active → paused / archived`，合法迁移才放行（防草稿直跳运行中）；**单 active**：激活新策略时旧 active 自动降级 paused；fork 生成新策略名（`multi_factor` → `multi_factor_v2`，version `v1.0 → v2.0`）。active 不可直接归档（需先暂停）。
2. **权重口径切换**：`strategy.factor_weights`（因子级、合计 1.0）**覆盖** `factor_definition.weight`，三处同步——Python `generate_signals` / `ReplayStrategy` / Go 排名分项；缺失因子回退 factor_definition，策略权重不完整仅告警不崩溃（评分侧 `f in factor_df.columns` 守卫）。
3. **A/B 按策略名对比**（契约 §5.4 初稿为 version 对比，fork 即新名，故落实现为 `?base=&candidate=` 两个策略名）：幂等建双 job（复用 `(strategy_name,start,end,top_n,fill_mode)` 唯一键），pending 轮询、done 组装 base/candidate/benchmark 净值与指标。**以设计文档 §3.3/§4.2 为准。**
4. **风控口径**：params 缺省 **0 = 规则关闭**（与引擎内置行为一致，避免静默改变历史回测）。生效语义镜像：止损 = `profit_rate ≤ -stop_loss_pct` 强制卖出当日可卖量（计入 RiskActions，不算常规 SellCount）；熔断 = `(历史峰值−总资产)/峰值 ≥ fuse_pct` 当日跳过策略 BUY（SELL/止损照常）；行业集中 = 加仓后该行业市值占比 > limit_pct 拒单。
5. **turnover/cost 口径**（§3.5）：`turnover = 累计买入成交金额/平均总资产×(252/交易日数)`；`cost = 累计(佣金+印花税+滑点)/平均总资产×(252/交易日数)`，落 `backtest_result`（DECIMAL(8,2)/(8,4)）。
6. **一致性对照延续 Iteration 2 模式**：Go 实盘风控 与 Python 引擎风控 共享**精确 2 位价格** fixture（Python 撮合不逐笔四舍五入，必须用整十价格使滑点精确）——止损/熔断/行业三组镜像用例 + turnover 手算用例。

## 实现

- `backend/internal/model/strategy.go`：Strategy 增 `zh_name/version/updated_at`，状态常量 draft/backtest/sample/active/paused/archived；FactorDefinition（构建器因子池）。
- `backend/internal/repository/strategy_repo.go`（新）：CRUD + GetActive（单 active）+ GetFactors + List 带 `latest_backtest_id`（最近回测任务 id）。
- `backend/internal/service/strategy.go`（新）：生命周期 service——Create/Update（仅 draft）/Fork（+1 版本）/Switch（状态机 + 单 active 降级 + 非法迁移拒绝）/List/Compare（A/B 幂等建 job + 状态组装）。
- `backend/internal/api/handler/strategy.go`（新）：`GET /strategies`（全量+元数据）、`POST /strategies`、`PUT /strategies/:name`、`POST /strategies/:name/versions`、`POST /strategies/:name/switch`、`GET /strategies/compare`、`GET /factors`。
- `backend/internal/service/backtest.go`：`CreateJob` 增 `strategy_name` 解析——空→GetActive（无则 `ErrBacktestNoActive`）、提供→校验存在非归档（404/40004、400/40001 映射）。
- `backend/internal/service/trading.go`（实盘）：`execStrategy` 读 active 策略 params（top_n/max_position_pct/stop_loss/drawdown_fuse/industry_limit），执行序 = **止损扫描 → 熔断（跳 BUY）→ SELL → BUY（行业集中）**；`RiskActions`/`Fused` 进 ExecResult、台账与飞书卡。
- `backend/internal/repository/account_nav_repo.go`：`GetPeakTotalAsset`（熔断峰值口径）。
- `quant-engine/app/strategies/multi_factor.py` + `app/tasks.py`：`generate_signals` 读 active 策略（status='active' 单 active），权重/参数用该行 factor_weights/params。
- `quant-engine/app/backtest_service.py`：`create_job`/`run_and_save` 按 strategy_name 加载权重与参数（`build_replay_strategy`），run 后落 turnover/cost。
- `quant-engine/app/backtest/engine.py`：风控镜像（`_stop_loss_scan`/`_drawdown_fused`/`_industry_over_limit`）+ `_generate_report` 算 turnover/cost；`portfolio.py`/`broker.py` 增 buy_amount/total_cost 累加器。
- `deploy/postgres/init.sql`：strategy 表增列 + 因子级种子（factor_weights 与 factor_definition 等值、params 含风控）、backtest_result 增 turnover/cost。**已有库由 GORM AutoMigrate 补列；种子 `ON CONFLICT DO NOTHING` 不覆盖已存在行**（见遗留）。
- `frontend-v2/`：`api/strategy.ts`（新：list/create/update/fork/switch/compare + factors）+ `types.ts` 补类型（StrategyInfo 元数据、Compare、FactorDefinition、turnover/cost、strategy_name）；**Backtest** 提交带 `strategy_name`、详情增「年换手/成本占比」KPI（4 列 ×2 行）；**StrategyFactory** 全量接通——三策略卡（active/候选/新建）、状态管理表（编辑/复制/状态推进）、构建器（GET /factors 真实因子池 + 滑杆配权 + 轮动/风控参数 → 存草稿）、A/B 真实净值与指标（轮询 pending）、寻优热力图保留 mock 标注。

## 遗留

1. **生产策略行是旧种子**（Iteration 0 初始化，`ON CONFLICT DO NOTHING` 永不更新）：`factor_weights` 为旧 category 级键（trend/value/quality/risk）、params **无风控三项**、无 version/zh_name。部署新代码后：
   - 信号/执行**不变**——category 键在评分侧被守卫安全忽略 → 权重回退 factor_definition（与现状一致）；params 无风控键 → 三项风控缺省 0=关闭（与现状一致）。
   - 但策略行元数据残缺 → 新 UI 显示 version/zh_name 为「—」。如需启用风控或版本化：开盘后用 UI「复制」出草稿重配再发布（权重与现状等值 → 信号仍不变）。
   - **风险点**：若生产库是**新种子**（params 含 `stop_loss_pct:0.15/drawdown_fuse_pct:0.10/industry_limit_pct:0.30`），部署即**首次激活**实盘风控（模拟账户，非真金；参数保守）。开盘前确认：`SELECT name,status,params FROM strategy;` —— params 含 `stop_loss_pct` 即属此情形。
2. **契约 §5.4 初稿偏差**：G11 初稿写 `compare?name=&base_version=&candidate_version=`（版本对比），落地为**按策略名** `?base=&candidate=`（fork 即新名，无版本并列表）。以设计文档 `策略与风控.md` §3.3/§4.2 为准，契约后续如需对齐可补注记。
3. **保留 mock（G9/G10，2.3）**：FactorLab/FactorFactory、参数寻优热力图（网格搜索后端超范围），页面保留 mock 并标注范围。
4. **walk-forward 自动验证不做**：状态机含 `sample` 态，滚动验证靠人工看 A/B 决定发布。
5. **沿用 Iteration 3 遗留**：`dev-up.sh` pid 记录到 wrapper 进程；调度器 `claim_job` 无锁（`FOR UPDATE SKIP LOCKED` 待评估）。
