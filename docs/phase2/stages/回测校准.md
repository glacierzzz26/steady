# Iteration 3：回测可信度校准（G8 T+1 成交假设）

> 归档模板：每个阶段一页，按五节填写。定稿设计见 [`../design/backtest-t1-可信度校准.md`](../design/backtest-t1-可信度校准.md)。
> 关联：接口契约 [`frontend-v2-api-contract.md`](../design/frontend-v2-api-contract.md) G8 · 进度总表 `../../进度总表.md`。

## 目标

消除回测的 **look-ahead bias（未来函数）**：原引擎信号在 T 日收盘生成、**同一时点成交**，高估了可用收益。本阶段引入两种**成交假设**并存对比：

- `t_close`：T 日收盘价成交（默认，兼容既有结果，含未来函数，仅作偏差基准）
- `t1_open`：T 日信号 → **T+1 开盘价成交**（保守假设，无未来函数，前端默认）

并以 **`t1_deviation`**（年化收益 T+1−T收盘）量化未来函数对业绩的高估程度，产出偏差报告校准回测可信度。

## 设计

核心决策（详见[定稿设计](../design/backtest-t1-可信度校准.md)）：

1. **fill_mode 是任务级参数，纳入幂等唯一键**：`(strategy_name, start_date, end_date, top_n, fill_mode)`。两种假设同区间可并存，互不覆盖——唯一索引从 4 列扩到 5 列，`on_conflict` 按 5 列命中。
2. **配对运行，一次 preload 复用**：单个 job 同时跑 primary + alt 两种模式（`run_and_save`），preload 一次后经 `_clone_strategy` **浅拷贝** `series/grid/_date_pos/pool` 给第二个实例，避免二次全量预计算，holdings 各自独立。
3. **成交语义差异**（`engine.py`）：
   - `t1_open`：当日先 `_execute_pending`（昨日入队信号按今日 open 成交）→ 再暂存当日新信号（仅 BUY/SELL）；成交价取 `open`。
   - `t_close`：维持即时成交（`close`）。
   - **边界**（均有 fixture 覆盖）：末日军只入队不成交；涨停（≥前收×1.10）买不进、跌停（≤前收×0.90）卖不出、当日买入冻结 T+1 卖出顺延、停牌（无 open）跳过、现金不足按 100 股递减。
4. **t1_deviation 口径**：`annualized_return(t1_open) − annualized_return(t_close)`，落在 `backtest_result`；前端 KPI 展示（正 = T+1 反而更好）。
5. **无迁移机制，schema 变更走手动 ALTER**：dev/prod 均需执行归档附带的迁移 SQL（新装走 `deploy/postgres/init.sql`）。

## 实现

- `quant-engine/app/backtest/engine.py`：`fill_mode` 参数、`pending_signals` 队列、`_get_fill_price`（t1_open→open）、`_execute_pending`、run() 重构、报告带 `fill_mode`。
- `quant-engine/app/backtest/replay.py`：preload 幂等 guard、select 增补 `DailyPrice.open`、`open_at()`。
- `quant-engine/app/backtest_service.py`：`create_job` 收 fill_mode 并纳入唯一键；`_clone_strategy` 浅拷贝；`run_and_save` 配对运行 + 算 `t1_deviation` 落库。
- `quant-engine/app/models/tables.py` + `deploy/postgres/init.sql`：`backtest_job.fill_mode`、`backtest_result.fill_mode/t1_deviation`、唯一索引扩 5 列。
- `backend/`：model / repo（OnConflict + GetByParams 带 fill_mode）/ service（校验枚举，默认 t_close）/ handler（DTO `fill_mode` 恒有 + `t1_deviation` omitempty）+ 单测（fill_mode 非法）。
- `quant-engine/app/cli.py`：`backtest --fill-mode` + `backtest-deviation` 偏差报告子命令。
- `quant-engine/tests/test_backtest_t1.py`：11 个 fixture 用例（核心语义 + 5 个边界 + 可复现 + 偏差来源 + 报告字段）。
- `frontend-v2/`：`fillMode` 默认 `'T+1开盘'`、提交带 `fill_mode`、历史表「假设」列、详情 KPI `repeat(6,1fr)` + `T+1偏差` 卡。

**修复**：`run_and_save` 完成日志格式串 `%+.2%%` 缺 `f` → `%+.2f%%`（Python logging 吞掉格式错误、只报内部 Traceback，不影响落库，但日志丢失）。

## 验收

- ✅ **单测**：quant-engine `pytest -q` **64 passed**（含 11 个新 T+1 用例）；Go `go test ./...` 全 ok；前端 `npm run build` 通过。
- ✅ **DB 迁移**（dev postgres）：`ALTER TABLE` + 重建唯一索引 `(strategy_name, start_date, end_date, top_n, fill_mode)`，`\d` 验证列 + 索引均在。
- ✅ **端到端 API**：`POST /backtests` 两种 fill_mode → job #11(t1_open) / #12(t_close) 均 done；`GET /backtests/:id` 返回 `fill_mode` + `t1_deviation`（互为镜像：−1.76% / +1.76%），nav 242 点。
- ✅ **偏差报告**：`python -m app.cli backtest-deviation --start 2024-01-01 --end 2024-12-31 --top-n 20` 输出对比表；2024 窗口 T+1 年化 +4.15% vs T收盘 +2.39%，偏差 **+1.76%（T+1 反而更好）**——买入延迟的损失被卖出延迟的收益抵消，验证偏差报告确能揭示非单调的时点效应。

## 遗留

- 运维发现：`dev-up.sh` 记录的 pid 是 nohup wrapper（stale），`kill $(cat .pid)` 打不到真实 python 进程；本次已手动按真实 pid 重启，建议后续脚本记录真实进程号。
- 调度器消费路径（`claim_job` `UPDATE...RETURNING`）无锁；本机并发极低不影响，但生产多进程场景需评估 `FOR UPDATE SKIP LOCKED`。
- G6 简报表增强字段维持空态（北向/A50 交易所停披或不可达，见契约注记），待生产环境落地。
- `turnover` 换手率字段延后至 Iteration 4（交易成本分析），前端已预留 `turnover?`。
