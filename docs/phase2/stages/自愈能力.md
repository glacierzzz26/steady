> 关联：进度总表 `../../进度总表.md` · GitHub issue #4（https://github.com/glacierzzz26/steady/issues/4）· 迁移 `deploy/migrations/005_remediation_task.sql`。

## 目标

飞书发出数据健康检查异常卡后，系统**自行诊断 → 补齐缺失股票 → 重新体检 → 重算因子/信号 → 回告绿卡**，全程无需人工。本期范围 P0 coverage（diff-repair 缺失股票）；missing_days/valuation/financial/benchmark 列 P1、price_anomalies/duplicates 列 P2；trade 不做自愈。

## 架构：两段式交接

Issue 设计写「consumer 在 collector」，但重跑 data_quality / 重算 factor→signal / 推飞书绿卡都是 quant-engine 模块（不同容器镜像，无法互相 import）。采用**两段式交接**，各守服务边界，DB 队列 `remediation_task` 为唯一交接介质：

```
producer（quant-engine job_data_quality 18:30，coverage fail 分支）
  └─ 插 remediation_task{trade_date, check_name='coverage', status='pending',
                          detail:{missing_codes:[...]}, attempts=0}
        （UNIQUE(trade_date, check_name) + ON CONFLICT DO NOTHING 防重）

stage1（collector 新模块 remediation.py，interval 5min）
  ├─ 领 pending → 读 detail.missing_codes → DailyCollector 逐只补 trade_date
  │   （现成 AkShare→新浪→BaoStock 源链 + cross_check_splits 除权守卫）
  ├─ 源被限（BaoStock 封禁/黑名单冷却，is_source_blocked 命中）→ 'source_blocked'，不重试
  ├─ 瞬时错误 → attempts+1；≥3 → 'failed'（红卡升级人工）
  └─ 修复成功 → 'repaired'

stage2（quant-engine 新 job_consume_remediation，interval 5min）
  ├─ 领 repaired → 重跑当日 coverage 检查
  ├─ 全绿 → compute_and_store + generate_signals（按日幂等覆盖）→ 'done'
  │        → 飞书绿卡「已自动修复」+ 修复行数（notify_config['remedi'] enabled 才推）
  └─ 仍红 → attempts+1；≥3 → 'failed'（红卡升级人工）；否则回 'pending' 再走 stage1
```

正常节奏：18:30 红卡 → 18:35 stage1 补齐 → 18:40 stage2 复检绿 → 绿卡；即使修复晚于 19:00（因子/信号已跑过），stage2 重算也因幂等 upsert 安全覆盖。

## 数据契约：remediation_task 表

迁移 `005_remediation_task.sql` + init.sql 5.x 段（新装实例），仿 `factor_trial`（003）注释风格、幂等可重放：

```sql
CREATE TABLE IF NOT EXISTS remediation_task (
    id            BIGSERIAL PRIMARY KEY,
    trade_date    DATE NOT NULL,
    check_name    VARCHAR(32) NOT NULL,     -- 本期仅 'coverage'
    status        VARCHAR(16) NOT NULL DEFAULT 'pending',
                 -- pending / repaired / done / failed / source_blocked
    attempts      INT NOT NULL DEFAULT 0,
    detail        JSONB,                    -- {missing_codes:[...], repaired_count, ...}
    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CONSTRAINT uq_remediation UNIQUE (trade_date, check_name)
);
```

两端各加 `RemediationTask` 模型（照 `FactorTrial` 样式），迁移 drift 检查要求 CREATE TABLE 内注释行必须内联（awk 解析限制）。

## 护栏（issue 必须项）

- **attempt 上限**：MAX_ATTEMPTS=3，5 分钟轮询天然隔开重试。
- **源被限立即中止**：BaoStock 封禁/冷却 → `source_blocked`，绝不反复轰被限源（08-28 事故根因）。
- **去重防轰炸**：remediation_task UNIQUE + ON CONFLICT DO NOTHING；绿/红卡走 task_run 去重。
- **trade 不做自愈**：不动 ExecuteDay。
- **修复成功才重算**：stage2 仅复检全绿后 compute_and_store / generate_signals（按日幂等覆盖）。
