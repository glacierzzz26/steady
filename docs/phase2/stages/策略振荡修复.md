# 策略振荡修复（实盘持仓重建）

> 前置：backtest 对照验证 [`策略振荡-backtest对照.md`](策略振荡-backtest对照.md)（2026-08-28 完成，确认修复方向）。本页为周末（2026-08-29）正式代码修复 + 验收。
> 关联：进度总表 `../../进度总表.md` · 记忆 `strategy-oscillation-fix-pending`。

## 目标

修复多因子轮动实盘振荡缺陷：`multi_factor._reconstruct_holdings` 把上一信号日 action ∈ {BUY, HOLD} 全视为持仓，HOLD 中「未持仓等回调」被误计 → 隔日 mass-HOLD（08-19:719、08-21:725、08-25:716）与 mass-SELL（08-20:704、08-24:695、08-27:686）交替。

修复方向（用户 08-27 拍板，backtest 对照已验证）：`_reconstruct_holdings` 改为从**真实持仓**（position 表）重建，与 Go ExecuteDay `ledger.positions` 同口径；回测侧默认持仓模式切 `portfolio`。

## 设计

实盘与回测两侧同步修复，确保闭环口径一致：

1. **实盘侧**：`_reconstruct_holdings` 从 `strategy_signal` 上一信号日重建 → 从 `position` 表主账户真实持仓重建（`account_id` = id 最小者，与 Go `GetPrimary` 同口径；`quantity > 0`）。signal 表只做信号记录，不再承担持仓来源。新增 `Account` ORM 模型（只读，DDL 以 init.sql 为准）。
2. **回测侧**：`replay.py` `holdings_mode` 默认 `running` → `portfolio`。`portfolio` 模式下引擎每交易日信号前把策略持仓同步为真实组合持仓（`engine.py` 钩子 2026-08-28 已实现），成交失败（涨停/资金不足/熔断）不产生幽灵持仓。`running`/`reconstruct` 保留供对照回归。
3. **附带 601162 回退**：`latest_by_announce` 取最新一期 col 非空值（跳过 null 期），与回测 `_asof_grid` 的 dropna 语义一致，消除 601162 天风证券最新一期 roe=null 被排除的边界。
4. **dev 库对齐**：dev 库从未跑过 `migrate.sh`（`schema_migrations` 不存在），缺 2.3b 列 + factor_stat/factor_corr/factor_trial 整表。跑 `scripts/migrate.sh` 应用 001~004（全幂等）补齐。
