## 0. 先说三件最重要的事

1. **这是一套模拟盘**：不连券商、没有真钱。所有「买入/卖出/持仓/净值」都是数据库里的模拟撮合，用来验证策略是否有效（`backend/internal/service/broker.go:55` 注释：`// Broker 模拟券商成交`）。
2. **PostgreSQL 是唯一通信中枢**：collector 写数据，quant-engine 读数据算因子/信号，backend 读信号做模拟交易。四个业务容器**互不调 HTTP**，全部绑定 `127.0.0.1`，只有 nginx 暴露 `:80`。
3. **数据源已从 Tushare 迁移到 BaoStock**（阶段 1~3，2026-08 完成）：`daily/calendar/index/valuation/finance/stock_basic` 全部走 BaoStock 主源 + AkShare 兜底，Tushare 依赖与配置面已移除。

## 1. 五个服务，一眼看懂

| 服务 | 语言 | 容器名 | 干什么 |
|---|---|---|---|
| `collector` | Python | quant-collector | 从 BaoStock/AkShare 采集行情/财务/估值/日历/热点 → 清洗 → 写库 |
| `quant-engine` | Python | quant-engine | 算因子 → 算信号 → 跑回测 → 因子检验/试算 → 组装早报 → 推飞书 |
| `backend` | Go | quant-backend | REST API + **模拟交易**（下单/持仓/净值/对账）+ LLM + 每日调度 |
| `frontend` | React+TS | quant-frontend | 网页 Dashboard（14 页），nginx `:80` 唯一入口 |
| `postgres` / `nginx` | — | quant-postgres / quant-nginx | 数据库 / 对外入口 |

数据流骨架：

```
A股数据源 (BaoStock 主源 + AkShare 兜底)
      │ 写
      ▼
┌──────────────┐   写     ┌─────────────────────────┐
│  collector   │─────────▶│      PostgreSQL          │
│  采集+清洗+回填 │         │ 行情/财务/估值/因子/信号   │
└──────────────┘          │ 账户/持仓/委托/成交/净值   │
      ▲                   └─────────┬────────────────┘
      │                             │ 读
      │                     ┌───────▼────────┐   ┌──────────┐
      │                     │ quant-engine   │──▶│ 飞书机器人 │
      │                     │ 因子/信号/回测/早报│   └──────────┘
      │                     └───────┬────────┘
      │                             │ 读信号
      │                     ┌───────▼────────┐   ┌──────────┐
      │                     │    backend     │──▶│ 云端 LLM  │
      │                     │ 模拟交易+API+调度 │   └──────────┘
      │                     └───────┬────────┘
      │                             │ /api/v1
      └─────────────────────┌───────▼────────┐
                           │ nginx :80 → 前端 │
                           └────────────────┘
```

## 2. 怎么打开系统

### 3.1 总览 `/dashboard`（`pages/Dash/index.tsx`）

每天打开看的第一页：账户赚没赚钱、策略跑没跑赢。

- **每日流水线示意条**：顶部静态展示 采集→因子→信号→交易→对账 的环节（`mock/data.ts` 的 `steps`，纯示意，真实任务状态见运维页）。
- **KPI 一行 6 个**：总资产（含累计收益率）、今日盈亏、超额收益（年化，vs 沪深300）、最大回撤、夏普比率（`—` 待后端直供）、今日信号（买/卖数量）。
- **策略净值 vs 指数**：折线图叠三条线——模拟账户净值 / 沪深300 / 上证指数，窗口与账户净值对齐（账户区间就绪后才请求指数，避免空窗）。超额收益就是用这两端算的年化差。
- **持仓快照**：当前持仓表（数量/成本/现价/盈亏），下方列出 可用资金 / 持仓市值 / T+1 冻结股数；空仓时给出「等待买入缓冲区出现新信号」提示条。
- **今日信号流**：最近 8 条信号（动作/证券/综合分/排名/理由）；空态「当日暂无信号」。
- **数据健康检查卡**：`/health/checks` 7 项每日体检（检查名/状态条/明细值，悬停看完整明细），与运维页同款组件。

依赖 API：`/account`、`/account/nav`、`/positions`、`/signals?action=BUY|SELL&page_size=1`、`/signals?page_size=8`、`/strategies`、`/index/nav/000300`、`/index/nav/000001`。

### 3.2 早盘简报 `/brief`（`pages/Brief/index.tsx`）

每天早上的「新闻摘要 + 昨日复盘 + 今日计划」，数据来自 quant-engine 09:10 组装的 `morning_brief.sections`。

- **KPI 一行 5 个**：简报日期、隔夜纳指、A50 期指（未产出→`—`）、北向资金昨日（未产出→`—`）、**两市成交昨日**（08-27 起已点亮，沪/深分开显示）。
- **隔夜外盘**：美股前夜（index code 以 `.` 开头），显示收盘与涨跌幅。
- **昨日热点板块**：涨跌幅条状图（按绝对涨幅归一），悬停显示领涨股。
- **昨日活跃个股**：涨停池/人气榜 TOP，显示涨跌幅与「N 连板」或行业。
- **昨日回顾**：账户净值（含当日收益）、信号执行（买/卖/总数 + 重点买入）、被拒委托（未产出）、当前持仓数与市值、数据健康（异常项计数 Tag）；有失败任务或交易消息会以提示条标出。
- **今日计划**：交易日历 checklist 时间线（09:00 股票池 → … → 19:30 信号）。
- **AI 解读**：调用 LLM 解读当日简报（`POST /llm/interpret-brief`），可「重新生成」；空态「暂无解读」。

依赖 API：`/morning-brief`、`/llm/interpret-brief`。G6 项诚实标注：A50/北向 未产出显示 `—`（`G6_HINT`）。

### 3.3 股票池 `/stocks`（`pages/Stocks/index.tsx`）

全市场约 800 只（沪深300 + 中证500）的评分总览，是「选股入口」。

- **KPI 一行 4 个**：股票池总数 / 沪深300 / 中证500 / 今日有效评分。
- **搜索**：输入代码或名称后回车过滤。
- **指数 Seg**：全部 / 沪深300 / 中证500 切换。
- **排序**：按代码 / 名称 / 上市日期。
- **表格**：代码、名称、指数标签、最新价、涨跌幅、成交额、PE、PB、ROE、综合分、排名、今日信号（Tag）。
- **行点击** → 跳 `/stocks/:code` 个股详情。

依赖 API：`/stocks`。综合分/排名/行情后端已实现（G2），页面顶部「今日有效评分」提示文案过时。

### 3.4 个股详情 `/stocks/:code`（`pages/StockDetail/index.tsx`）

单只股票的完整档案：K线 + 因子雷达 + 财务 + 信号历史。

- **头部**：返回股票池、名称代码、沪深300/中证500 标签、当前持仓 Tag（实时查持仓表比对）、最新收盘价与涨跌幅。
- **日K · 前复权**：ECharts 蜡烛图 + 成交量副图（`/kline/:code?period=day&adjust=qfq`）；「日线/周线/月线」Seg 目前只有日线可用（周/月未接线）。
- **因子得分**：雷达图（趋势/价值/质量/风险 四维）+ 综合分（/100）+ 横截面排名 + 今日信号；缺因子时整卡空态。
- **财务指标**：近 10 期报告期，ROE/净利同比/毛利率/资产负债率，**按公告日对齐**（防未来函数，页面上有标注）。
- **信号历史**：近 10 个交易日信号（日期/动作/综合分/排名，悬停显示 reason）。

依赖 API：`/stocks/:code`、`/kline/:code`、`/stocks/:code/financial`、`/stocks/:code/signal-history`、`/positions`（持仓命中判定，失败静默视为未持仓）。

### 3.5 信号 `/signal`（`pages/Signal/index.tsx`）

看「今天系统让买什么卖什么」，含因子分项可解释理由。

- **策略卡**：当前策略的状态 / 参数 / 因子权重（来自 `/strategies`）。
- **KPI**：今日买入 / 卖出 / 持有 数量。
- **信号明细表**：动作 Tag、排名、代码、名称、综合分、趋势 / 价值 / 质量 / 风险 分项、PE、20 日涨幅；行悬停显示 reason。
- **Seg 过滤**：全部 / 买入 / 卖出 / 持有；下方分页器翻页。

依赖 API：`/strategies`、`/signals`。因子分项后端已返回（G1），页面里的 `待 G1` 提示是过时文案。

### 3.6 因子实验室 `/factor`（`pages/FactorLab/index.tsx`）

「研究哪个因子有用」——G9 因子检验统计（quant-engine 19:05 预计算写 `factor_stat`/`factor_corr`，后端只读表轻聚合）。

- **因子卡片网格**：每因子一张卡，显示 IC 均值（IC20）、状态（按 ICIR 阈值 有效≥0.3 / 存疑≥0.1 / 无效 / 无数据）、ICIR 与方向（正向/反向）、权重条；**点击卡片切换**下方明细。
- **RankIC 时序**：选中因子日度 IC 柱状 + 累计线（`/factors/:name/stats`）。
- **IC 衰减曲线**：全部因子叠加，预测窗口 1~60 日区间均值。
- **分层收益**：选中因子 Q1~Q5 组均前向收益（H=5），图例附「单调性 Q1 跑赢 Q5」比例。
- **因子相关性矩阵**：6×6 Spearman 区间均值热力图（`/factors/stats/correlation`）。
- **权重实验台**：滑杆模拟重新配权、实时显示合计与总分预览；「以此权重发起回测」按钮目前只是占位（未接线）。

依赖 API：`/factors`、`/factors/:name/stats`（每因子并行拉，单因子失败不拖垮整页）、`/factors/stats/correlation`。

### 3.7 因子工厂 `/factor-factory`（`pages/FactorFactory/index.tsx`）

「调因子参数、试算检验、管理版本」——G10 因子生命周期 + 试算/寻优（quant-engine 每 5 分钟消费 `factor_trial` 队列）。

- **分区导航**：左侧 STEP 1~5（因子池/参数配置/试算检验/版本管理/参数寻优），滚动自动高亮当前区。
- **因子定义池**：`factor_definition` 全量（6 基础 + fork 变体），显示分类/权重/状态 Tag；点击载入参数配置。
- **参数配置**：基础因子才有计算参数（ma_trend：短/长均线；macd_signal：快/慢/信号线；value/quality/risk 无参数则提示「as-of 取值，参数输入不适用」）；选区间 → **发起试算**（单组）或 **发起寻优**（网格）。
- **试算结果**：提交后每 2.5s 轮询 `/factor-trials/:id`，展示 RankIC 均值（达标>0.03）、ICIR（达标>0.3）、IC 时序、单调性、衰减、分层图；失败显示 Notice。
- **版本管理**：状态流转 草稿→试算中→检验中→**已上线**→已停用，按状态给可用操作（提交试算/通过/回炉/上线/停用/新版本/删除）；**新版本（fork）** 自动生成 `_v2/_v3` 并带 params 快照；删除仅草稿、已有试算/评分记录则拒。
- **参数寻优**：每个参数填候选值（逗号分隔）+ horizon 候选 → 提交后热力图（参数轴 × 持有期 IC 均值）。解读提示：轴多格都稳定=因子对参数不敏感（好信号），只有孤立一格亮=过拟合。

依赖 API：`/factors`、`/factor-trials`、`POST /factors/:name/trial|optimize`、`/factors/:name/versions|switch`、`DELETE /factors/:name`。公式编辑器是产品愿景（当前仅支持对已有因子的参数化重算）。

### 3.8 策略工厂 `/strategy-factory`（`pages/StrategyFactory/index.tsx`）

「改策略权重/参数、走状态机发布、A/B 对比」——G11 策略生命周期（单 active 不变量由后端强制）。

- **三策略卡**：运行中（active，绿色边框，显示版本/因子数/轮动参数/回测依据）、候选（草稿或验证中，可「载入构建器」或「发布上线」）、新建草稿入口。
- **策略状态管理表**：状态机 草稿→回测验证→样本外→**运行中**→已暂停（可重新启用或归档）；每行给「复制 / 推进 / 删除」操作；发布上线需二次确认（当前 active 自动降级暂停，旧持仓按卖出缓冲自然退出，不强制清仓）。
- **策略构建器**：因子池勾选 + 滑杆配权（保存时归一为 1.0）、轮动参数（top_n / 买入缓冲 / 卖出缓冲）、风控参数（单票仓位上限 / 个股止损 / 组合回撤熔断 / 行业集中度，0=关闭）；仅草稿可保存 → 「存为草稿」或「发起 A/B 回测」。
- **参数寻优热力图**：top_n × buy_buffer 年化热力图——**示意（mock 数据）**，Iteration 4 不落地，真实寻优在因子工厂。
- **A/B 对比**：选基准/候选 + 区间 + 成交假设（T+1开盘/T日收盘）→ 净值叠加图 + 指标对比表（总收益/年化/回撤/夏普/年换手/成本占比/成交笔数，更优列高亮）；pending 时每 3s 轮询，已跑过的区间秒回（幂等复用）。

依赖 API：`/strategies`、`/factors`、`/strategies/compare`、`/strategies/:name/versions|switch`、`POST/DELETE /strategies`。

### 3.9 模拟交易 `/trade`（`pages/Trade/index.tsx`）

模拟盘的「账户」页：钱、持仓、委托、规则一览。

- **KPI 一行 5 个**：总资产（含累计盈亏 vs 初始资金）、可用资金（占比）、持仓市值（只数+占比）、累计手续费（佣金+税分开）、成交笔数（买/卖分开）。
- **模拟盘规则卡**：成交价（收盘±0.1% 滑点）、T+1·整手 100 股、佣金万 2.5 最低 5 元、印花税万 5 仅卖出、涨跌停分板块；下方黄色提示「当前按 T 日收盘价撮合，存在乐观偏差，切换 T+1 假设见回测中心」。
- **账户净值曲线**：模拟盘启动以来总资产走势。
- **持仓明细**：证券/持仓/可卖/成本价/现价/市值/浮动盈亏；`可卖 < 持仓` 时标 `(冻结)`（T+1）。
- **委托记录**：时间/方向/证券/委托量/成交量/成交价/状态（PENDING 待成交 / FILLED 已成 / REJECTED 已拒 / CANCELLED 已撤）。

依赖 API：`/account`、`/account/nav`、`/positions`、`/orders`、`/trades`。注：本页没有真实「下单」入口（下单表单未接线，唯一触发模拟撮合的是手动执行按钮，见 §9 CLI）。

### 3.10 回测中心 `/backtest`（`pages/Backtest/index.tsx`）

跑历史区间验证策略，含「T 日收盘 vs T+1 开盘」两种成交假设对比（G8）。

- **发起回测表单**：选策略（标 active）、回测区间、top_n 滑杆（5~50）、成交时点假设 Seg（T日收盘=乐观含未来函数 / T+1开盘=保守无未来函数，结果自动附年化偏差）→ 提交后显示 job #id。
- **回测历史**：近 20 条列表（ID/策略/区间/top_n/假设/总收益/年化/最大回撤/夏普/超额/状态），点击行加载下方详情；每行可勾选（仅已完成任务）。
- **历史任务横向对比**：勾选 ≥2 条已完成 → 指标并排对比表（每行最佳列高亮）+ **归一化净值叠加图**（含沪深300基准，最多 5 条）；混用 T 收盘/T+1 开盘假设时给出口径警示。
- **回测详情**：策略净值 vs 沪深300 曲线 + 8 个 KPI：总收益/年化收益/最大回撤/夏普/超额收益/**T+1偏差**（年化 t1_open−t_close）/年换手/成本占比。

依赖 API：`/strategies`、`/backtests`、`/backtests/:id`、`POST /backtests`。

### 3.11 运维监控 `/ops`（`pages/Ops/index.tsx`）

## 5. 代码架构（四层逐层看懂）

### 5.1 collector —— 数据采集层（Python）

目录结构：

```
collector/app/
├── cli.py                # 手动入口（sync-* / backfill / backfill-valuation）
├── tasks.py              # APScheduler 定时任务（08:45~18:15 各 job）
├── config.py             # 环境变量配置（限速/区间/数据源开关）
├── db.py                 # SQLAlchemy 会话
├── models/tables.py      # ORM 表（与 init.sql 一一对应）
├── sources/
│   ├── __init__.py       # 数据源适配层入口
│   └── baostock.py       # BaoStock 适配层（懒登录单例 + 同形状输出 + 兜底降级）
├── cleaners/
│   └── factor_guard.py   # 复权因子除权一致性守卫（阶段 3 新增）
└── collectors/           # 每类数据一个采集器
    ├── base.py           # 基类（build_rows/save/重试/限速共用）
    ├── stock.py          # 股票列表 + 股票池标记
    ├── calendar.py       # 交易日历
    ├── daily.py          # 日行情（OHLCV + adj_factor）
    ├── valuation.py      # 日度估值（PE/PB/市值）
    ├── finance.py        # 财务指标（报告期 + 公告日）
    ├── index.py          # 指数行情（sh000001/sh000300/sh000905/sz399106）
    ├── hotspot.py        # 市场热点（早盘简报数据源）
    └── backfill.py       # 历史回填（分批限速、断点续传、幂等）
```

**数据源策略（阶段 3 后）**：所有采集器兜底链 = **BaoStock 主源 → AkShare 降级**。`config.py` 里 `BAOSTOCK_ENABLED` × `BAOSTOCK_SOURCES` 控制每个 scope 是否走 BaoStock；scope 命中才用 BaoStock，否则直接 AkShare。BaoStock 是自定义 TCP 协议，`sources/baostock.py` 实现**懒登录单例 + 失效重连 + socket 超时**，逐只循环只登录一次；查询结果与 AkShare **同形状**，上层 build_rows/save/清洗逻辑完全不动。

**复权语义（8/26 茅台/九号实测确认）**：`adjustflag="1"` = 后复权（派生 adj_factor 必须用它）；`"3"` = 不复权（入库 close 用这个）。成交量股 → ÷100 转手，对齐东财。

**factor_guard（阶段 3 核心新增）**：`build_rows` 由 hfq/raw 派生 adj_factor，入库前校验「因子阶跃必须对应价格跳空」（后复权连续性 `step = f[d]/f[d-1]−1 ≈ gap = close[d-1]/close[d]−1`，容差 `max(0.07, 0.5·|step|)`）。不符 → **整段拒收**，该股降级 AkShare 保单源一致。实证拒收平安银行 2020-12-31 虚假调整 16.7%、天齐锂业 2020-01-02 滞后调整 16%。残余误伤面 = 纯大跌日（step≈0 但 gap>7%），由对账脚本 `rewrite_adj_factor.py --reconcile` 的比值二次校验兜底。

**限频**：`RATE_LIMIT_SECONDS`（默认 3s/只）回填用；`DAILY_SYNC_INTERVAL`（默认 1s/只）每日增量用。BaoStock 免费源并发过载会触发黑名单（错误码 10001011），全量对账须低并发 + `--sleep` 限频。

### 5.2 quant-engine —— 因子/信号/回测引擎层（Python）

目录结构：

```
quant-engine/app/
├── cli.py                # 手动入口（factors/signals/backtest/backtest-deviation/factor-stats）
├── tasks.py              # APScheduler 定时任务（09:10~19:30 + 5 分钟消费者）
├── factor_service.py     # 因子计算 + 横截面归一 + 综合分（核心）
├── factors/              # 因子公式实现
│   ├── trend.py          #   ma_trend（MA5>MA20）、macd_signal（DIF>DEA）
│   ├── value.py          #   pe_ratio、pb_ratio
│   └── financial.py      #   roe_quality、debt_risk（按公告日 as-of）
├── strategies/
│   ├── base.py           # Strategy 基类 + Signal
│   └── multi_factor.py   # 唯一实际策略：多因子轮动（BUY≤15 / SELL>30 / 其余 HOLD）
├── backtest/             # 回测引擎（broker/portfolio/engine/replay）
├── backtest_service.py   # 回测任务消费者（DB 队列）
├── factor_research.py    # G9 因子检验统计预计算（Rank IC/ICIR/衰减/分层/相关）
├── factor_trial.py       # G10 试算/寻优任务消费者
├── data_quality.py       # 18:30 数据健康检查（7 项）
├── morning_brief.py      # 09:10 早盘简报组装
├── notify.py             # 飞书推送
├── notify_scheduler.py   # 每分钟通知 tick（到点推送 + 该做没做监控）
├── task_run.py           # 任务台账
└── models/tables.py      # ORM 表
```

**因子计算**（`factor_service.py`）：每只股票每天 6 个因子 → winsorize（1%/99%）→ 横截面百分位 rank → 按方向翻正 → normalized 0~1；综合分 `score = 100 × Σ(weight × normalized)`，缺任何因子剔除（保证排名公平）。三个 as-of 防未来函数：财务按公告日、估值按 30 日回看、行情用前复权价。

**策略**（`multi_factor.py`）：`rotation_action(rank, held, buy_buffer, sell_buffer)` —— 未持仓且排名 ≤15 → BUY；已持仓且排名 >30 → SELL；其余 HOLD（16~30 缓冲带防频繁换手）。持仓从**最近一次历史信号重建**（昨日 action ∈ {BUY,HOLD} 视为持有）。
> ⚠️ **已知缺陷**：重建把「未持仓等回调的 HOLD」误计为持仓 → 实盘 mass-HOLD 日与 mass-SELL 日隔日振荡（08-19:719 / 08-20:704）。backtest 对照已实证 `portfolio` 模式（引擎真实持仓同步）能消除振荡，**修复推到周末（08-29/30）**，依据见 `docs/phase2/stages/策略振荡-backtest对照.md`。

**回测引擎**（`backtest/`）：`engine.py` 主循环按日历逐日：unfreeze → mark-to-market → stop-loss → 熔断 → 执行 pending → 信号 → 净值。`fill_mode` = `t_close`（当日收盘成交，含未来函数）/ `t1_open`（T+1 开盘成交，无未来函数，T 日信号暂存）。`holdings_mode`（振荡对照新增）= `running`/`reconstruct`/`portfolio`，默认 `running`。风控（止损/回撤熔断/行业集中）与 Go 实盘同口径。

## 8. 部署与发布（三件套模型）

```
dev 分支（日常开发） ──发布时──▶  master（生产唯一来源） ──build-release.sh──▶  deploy/release/steady-<日期>-<SHA>/ ──scp──▶  VM
```

- **开发在 dev，发布只走 master**。`build-release.sh` 校验当前分支，非 master 拒绝打包。
- 发布动作：`git checkout master && git merge dev && git push` → 本地 `./scripts/build-release.sh` → `scp -r deploy/release/steady-* user@vm:~` → VM 上 `cd ~/steady-* && ./install.sh`。
- `install.sh` 自动：检测既有部署 → 复用 compose 项目名与数据库密码 → 加载镜像 → `compose up -d` → 按序应用 `deploy/migrations/*.sql` → 写 RELEASES.md。
- 数据库在命名卷 `steady_postgres_data`，**升级/回滚都不动数据**。回滚 = 进旧版本目录再跑一次 install.sh。
- 备份：宿主机 cron 每天 02:30 `scripts/backup-db.sh` 全库 gzip 到 backup/，留 30 份。
- 安全基线：仅内网、API 无鉴权（不直接暴露，只走 nginx:80）、`.env` chmod 600。

> schema 变更两条规矩（已踩两次 `column does not exist` 坑）：① 同步更新 `deploy/postgres/init.sql`（全新装）② 新增幂等迁移 `deploy/migrations/NNN_描述.sql`（旧库升级）。`migrate.sh --check` 可查列漂移。
